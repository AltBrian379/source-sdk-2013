OWTF2 - Demoman animations (TF2), for the Crusader's placeholders
===================================================================
Read from TF2's own model files (tf2_misc_dir.vpk, 2026-10-21) by parsing each .mdl's sequence
table: sequence name, the activity it answers to, and whether it loops. Code plays activities,
not sequence names (SendWeaponAnim / DoAnimationEvent -> activity -> a sequence with it; when
several sequences share an activity, one is picked at random, e.g. b_swing_a / b_swing_b).

The Crusader's choices (which of these it uses, and why) are in docs/crusader-plan.txt,
section "Animations".

Models
- Viewmodel arms: models/weapons/c_models/c_demo_arms.mdl ("model_hands" in crusader.txt).
  Its sequences come from c_demo_animations.mdl ($includemodel); the arms file itself only has
  the names, no activities. Weapon models (c_demo_cannon, c_demo_sultan_sword, ...) only have
  an idle: all hand animation is in the arms.
- World model: models/player/demo.mdl. It includes demo_animations.mdl (the activities),
  demo_user_animations.mdl (user_ref only) and
  models/workshop/player/animations/demo_workshop_animations.mdl (community taunts).

How TF2 picks them
- Viewmodel: CTFWeaponBase translates generic ACT_VM_* by the weapon's type
  (tf_weaponbase.cpp table): ACT_VM_HITCENTER on a melee weapon -> ACT_MELEE_VM_HITCENTER,
  on a primary -> ACT_PRIMARY_VM_*, and so on. The swords (CTFSword, tf_weapon_sword.cpp)
  translate to the *_SPECIAL set instead (cm_* sequences, the two-handed claymore swings).
  ACT_VM_SWINGHARD is the crit swing.
- World model: the player anim state plays ACT_MP_<action>_<slot>, the slot coming from the
  item's "anim_slot" (items_game.txt) or the weapon type. The sword prefab (weapon_sword:
  Eyelander, Claidheamh Mor, Persian Persuader, Half-Zatoichi, ...) uses anim_slot "item1",
  so its third-person swing is attackstand_ITEM1 (the two-handed overhead swing). The bottle
  uses "melee" (Melee_Swing); all-class melees use MELEE_ALLCLASS.
- Shield charge: there is no charge sequence in either model. TF2 plays the normal run of the
  active weapon's slot while TF_COND_SHIELD_CHARGE is on (the shield is a wearable).

Which weapon plays which (by activity, which is what counts): the weapon scripts (TF2's .ctx,
decrypted) give the grenade launcher WeaponType "primary" and the stickybomb launcher
"secondary". So the grenade launcher plays the sb_* sequences (ACT_PRIMARY_*) and the sticky
launcher the g_* ones (ACT_SECONDARY_*; g_auto_fire = ACT_SECONDARY_VM_PULLBACK is the sticky
charge-up): the name prefixes don't match the weapons. loch_* is the Loch-n-Load's reload
(ACT_PRIMARY_*_2). b_* = the bottle and the other melees (WeaponType "melee"), cm_* = the
swords (tf_weapon_sword.ctx is also "melee"; CTFSword maps to *_SPECIAL), melee_allclass_* =
all-class melees, throw_* = throwables (Jarate-like), spell_* = Halloween spells, grapple_*,
PASSTIME_*.

World model sequences with an activity (demo_animations.mdl). Sequences without one
(aimmatrix_*, layer_*, armslayer_*, bodylayer_*, a_*_reload helpers, jumplandPose_*, swimAlign_*,
death poses, taunts) are blend layers or are played by name and are left out here; taunts are
listed at the end.
